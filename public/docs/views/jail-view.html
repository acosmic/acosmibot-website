Jail System

An opt-in reaction-ballot Chaos feature that temporarily confines eligible members to one configured channel without replacing Discord's formal moderation tools.

Opt-in reaction ballots

Jail is configured per server from the dashboard. An administrator chooses the trigger reaction, vote threshold, ballot window, eligible channels, protected roles, sentence duration, and optional mod-log channel. The feature is disabled by default.

Overview

A qualifying reaction opens one durable ballot, and later reaction changes edit the same tracker embed. When the threshold is reached, the target loses access to regular server channels and is confined to the configured Jail channel for the sentence. Once the time expires — or a moderator releases them early — only Jail-touched permission fields are restored.

Key Features

  • Temporarily restrict members to a single #jail channel
  • Set a sentence from 1 minute to 7 days
  • Automatic release when the timer expires
  • Moderators can send, release, list, and inspect cases
  • The jailed member can still read and send messages in the jail channel
  • Member-specific permission snapshots restore access safely
  • Owners, administrators, bots, webhooks, and protected roles are immune

Commands

/jail send <member> [duration_minutes] [reason]
Manually confine a member using the configured Jail channel and permission checks. Requires Manage Guild or Moderate Members at runtime.

Examples:

/jail send @username 30 Spamming in #general /jail send @username 1440 Repeated rule violations
/jail status [member]
Inspect one member or privately list active cases and release times.
/jail release <member> [reason]
Release a jailed member before their sentence expires and restore only the permissions Jail changed.

Example:

/jail release @username
/jail list
View active cases and remaining sentence time privately.

Example:

/jail list

Setup

Before using the Jail system, a server admin needs to configure the Jail channel, trigger, ballot safeguards, protected roles, and sentence in the Jail dashboard surface.

1

Create a #jail channel

Create a dedicated text channel where jailed members will be confined. The bot applies member-specific overwrites when a case starts.

2

Configure in the dashboard

Open the /server dashboard, open Chaos → Jail, and select the channel, trigger emoji, vote settings, protected roles, and sentence controls.

3

Verify bot permissions

Ensure Acosmibot can view, send, and read history in the source and Jail channels, and has Manage Roles. Connected voice targets also require Move Members.

4

Start a case

Members can react with the configured emoji in an eligible channel. Moderators can use /jail send for a direct case.

How It Works Technically

When a member is jailed, Acosmibot uses member-specific Discord channel permission overwrites to deny access to regular channels while allowing the configured Jail channel. On release — automatic or manual — the saved tri-state fields are restored without replacing unrelated administrator changes.

Permission Flow

  • Member-specific overwrites deny View Channel on regular channels
  • The jail channel explicitly allows View Channel and Send Messages for the jailed member
  • When released, the saved Jail fields are restored without replacing unrelated permissions

Permission and immunity notes

  • Acosmibot needs Manage Roles to edit member-specific channel overwrites
  • Connected voice members additionally require Move Members
  • Server owners cannot be jailed
  • Admins with "Administrator" permission may bypass the jail channel restriction — consider this when structuring roles

Sentence duration reference

Dashboard sentence durations are configured in whole minutes, from 1 minute through 7 days.

Best Practices

Tips for Moderators

  • Always include a reason so both the member and your mod team understand the context
  • Use short durations (10–60 minutes) for first offenses or minor disruptions
  • Reserve longer sentences for repeat offenders or more serious violations
  • Check /jail list regularly so no one is accidentally left jailed past their intended sentence
  • Consider posting a pinned message in #jail explaining the process and what the member needs to do to be released

Things to Avoid

  • Don't jail members as a joke — it removes real access and can be disorienting
  • Avoid indefinite jails; if a member needs a permanent restriction, a ban or role removal is more appropriate
  • Don't set excessively long durations without a clear policy — consistency builds trust in your moderation team

Frequently Asked Questions

Q: Can a jailed member see that they're in jail?

A: Yes. They can read and send messages in the jail channel, so they're aware of their situation. The bot posts a message in the jail channel notifying them of the duration and reason.

Q: What if the bot goes offline during a jail sentence?

A: The jail timer is stored in the database. When the bot comes back online, it checks for expired sentences and releases any members whose time has passed.

Q: Can jailed members still use DMs?

A: Yes. The jail system only affects server channel access. Direct messages are unaffected.

Q: Can I jail someone who already has a role higher than mine?

A: Owners, administrators, and members with configured protected roles are immune to reaction ballots. A direct moderator send still performs the same safety checks.

Q: Is there a mod log for jail actions?

A: Yes, if you have a mod-log channel configured in the dashboard, Jail events can be recorded there with the target, duration, and reason.
